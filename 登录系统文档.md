# 登录系统文档

## 概述

本系统包含两个前端应用，它们共享一套统一的登录认证体系：

| 应用 | 路径 | 功能 |
|------|------|------|
| user-web | `user-master/user-web/` | 登录页面，支持多种登录方式 |
| mediahub-web | `mediahub-web/` | 主站应用，展示内容与上传功能 |

## 二、登录方式

### 2.1 支持的登录方式

| 登录方式 | 说明 | 使用场景 |
|---------|------|---------|
| **微信扫码** | 用户使用微信扫二维码完成授权 | 移动端用户、主要登录方式 |
| **GitHub** | 使用 GitHub 账号 OAuth 授权 | 开发者、技术用户 |
| **GitLab** | 使用 GitLab 账号 OAuth 授权 | 企业内部 GitLab 用户 |

### 2.2 登录方式获取接口

**接口**: `GET /v1/login/methods`

**请求参数**:
```typescript
{
  sys: string  // 系统标识，如 "ai"
}
```

**响应数据**:
```typescript
{
  data: {
    github: string,      // GitHub OAuth 授权跳转 URL
    gitlab: string,      // GitLab OAuth 授权跳转 URL
    wx_qrcode: {
      expire_seconds: number,  // 二维码有效期（秒）
      ticket: string,          // 二维码凭证
      qr_code_url: string     // 二维码图片 URL
    }
  }
}
```

### 3.2 轮询机制

```typescript
// 轮询检查扫码状态
let count = 0;
const timer = setInterval(() => {
  loginOfficialCallback({
    sys: sys,
    ticket: data.loginMethods.wx_qrcode.ticket.value
  }).then((res) => {
    // 检查是否登录成功
    if (res.data && res.data.redirect_url != "") {
      clearInterval(timer);  // 停止轮询
      window.location.href = res.data.redirect_url;  // 跳转
    }

    count++;

    // 二维码有效期：最多轮询 180 次（约 3 分钟）
    if (count >= 180) {
      clearInterval(timer);
      ElMessage({
        showClose: true,
        message: "二维码已过期，请刷新页面",
        type: 'error',
      });
    }
  }).catch((res) => {
    clearInterval(timer);
    ElMessage({
      showClose: true,
      message: res.message,
      type: 'error',
    });
  });
}, 1000);  // 每秒轮询一次
```

### 3.3 轮询参数说明

| 参数 | 说明 |
|------|------|
| `sys` | 系统标识，区分不同产品 |
| `ticket` | 二维码凭证，标识当前二维码 |
| `count` | 轮询计数器，控制二维码有效期 |
| `interval` | 轮询间隔，1000ms = 1秒 |

### 3.4 登录成功判断

```typescript
// 条件：res.data 存在且 redirect_url 不为空
if (res.data && res.data.redirect_url != "") {
  // 登录成功，跳转到 redirect_url
  window.location.href = res.data.redirect_url;
}
```

## 五、身份认证机制

### 5.1 JWT Token 存储

**存储位置**: Cookie

**Cookie 名称**: `sso_0voice_access_token`

**设置方式**: 后端在登录成功后设置

```typescript
// Cookie 格式
document.cookie = "sso_0voice_access_token=xxx; expires=...; path=/"
```

### 5.2 JWT Token 结构

JWT (JSON Web Token) 由三部分组成，用 `.` 分隔：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    JWT Token 结构                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   eyJhbGciOiJIUzI1NiJ9 . payload . signature                       │
│   ────────────────    ───────────    ──────────                    │
│        Header        Payload       Signature                        │
│                                                                     │
│   Header (头部):                                                     │
│   {"alg":"HS256","typ":"JWT"}                                       │
│                                                                     │
│   Payload (载荷) - 包含用户信息:                                    │
│   {                                                                │
│     "user_id": 12345,          // 用户 ID                          │
│     "name": "张三",            // 用户名                            │
│     "avatar": "https://...",    // 头像 URL                         │
│     "exp": 1625123456          // 过期时间 (Unix 时间戳)           │
│   }                                                                │
│                                                                     │
│   Signature (签名):                                                  │
│   HMACSHA256(                                                    │
│     base64UrlEncode(header) + "." + base64UrlEncode(payload),      │
│     secret                                                          │
│   )                                                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.3 Token 解析

前端解析 JWT 获取用户信息：

```typescript
// 从 Cookie 获取 Token
let access_token = getCookie("sso_0voice_access_token");

// 分割 Token
let list = access_token?.split(".");  // ["header", "payload", "signature"]

if (list) {
  // Base64 解码 payload (第二部分)
  let decoded = atob(list[1]);

  // 解析 JSON
  let userInfo = JSON.parse(decoded);
  // {
  //   user_id: 12345,
  //   name: "张三",
  //   avatar: "https://...",
  //   exp: 1625123456
  // }
}
```

### 5.4 Token 解析函数

```typescript
// 完整解析流程
function parseUserInfo(access_token: string) {
  // 1. 分割 JWT
  const parts = access_token.split('.');

  // 2. Base64 解码 payload
  const payload = atob(parts[1]);

  // 3. JSON 解析
  const userInfo = JSON.parse(payload);

  return userInfo;
}
```

## 六、请求拦截器

### 6.1 自动添加 Token

每次发送 HTTP 请求时，拦截器自动从 Cookie 获取 Token 并添加到请求头：

```typescript
// axios 请求拦截器
service.interceptors.request.use(function (config) {
  // 从 Cookie 获取 Token
  let access_token = getCookie("sso_0voice_access_token");

  // 如果 Token 存在，添加到请求头
  if (access_token) {
    config.headers.Authorization = "Bearer " + access_token;
  }

  return config;
}, function (error) {
  return Promise.reject(error);
});
```

### 6.2 请求头格式

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.payload.signature
```

**说明**:
- `Authorization`: HTTP 标准授权头
- `Bearer`: OAuth 2.0 推荐的令牌方案
- `Token`: JWT 字符串

### 8.2 删除 Cookie 原理

```typescript
function deleteCookie(name: string) {
  // 将过期时间设置为 1970 年 1 月 1 日
  // 浏览器检测到过期，会自动删除该 Cookie
  document.cookie = `${name}=; expires=Thu, 01 Jan 1970 00:00:00 GMT; path=/`;
}
```

## 九、错误处理

### 9.1 HTTP 状态码处理

| 状态码 | 说明 | 用户提示 |
|--------|------|---------|
| 500 | 服务器内部错误 | "服务器内部错误" |
| 504 | 网关超时 | "网关超时" |
| 413 | 请求体过大 | "仅支持上传20M以内的图片" |
| 无响应 | 网络错误 | axiosErr.message (原始错误信息) |

### 9.2 错误处理代码

```typescript
service.interceptors.response.use(
  function (response) {
    return response;
  },
  function (error) {
    const axiosErr = error as AxiosError;

    if (!axiosErr.response?.status) {
      // 网络错误
      ElMessage({
        showClose: true,
        message: axiosErr.message,
        type: 'error',
      });
    } else if (axiosErr.response?.status == 500) {
      ElMessage({
        showClose: true,
        message: "服务器内部错误",
        type: 'error',
      });
    } else if (axiosErr.response?.status == 504) {
      ElMessage({
        showClose: true,
        message: "网关超时",
        type: 'error',
      });
    } else if (axiosErr.response?.status == 413) {
      ElMessage({
        showClose: true,
        message: "仅支持上传20M以内的图片",
        type: 'error',
      });
    }

    return Promise.reject(error);
  }
);
```

## 十四、常见问题

### 14.1 Token 过期处理

前端应定期检查 Token 过期时间，或在后端返回 401 时引导用户重新登录。

### 14.2 跨域问题

如果 API 和前端不在同一域名，需要后端配置 CORS 允许跨域请求。

### 14.3 二维码刷新

二维码有效期默认 3 分钟（180 秒轮询），过期后需要刷新页面重新获取。

### 14.4 登录回调地址

不同系统可能使用不同的回调地址，通过 URL 参数 `sys` 区分。
